# 接入聊天软件

本项目不包含任何聊天软件的桥接，也不登录任何聊天账号，只提供一个接口：网关 `rhine-gateway`。聊天软件一侧由**连接器**负责：连接器把新消息交给网关，再把角色的回复发回原会话。连接器需自行编写或另行获取，按[连接器协议](protocol.md)与网关通信。任何聊天软件，只要有实现该协议的连接器，即可接入。

```
聊天软件 ⇄ 连接器（不属于本项目） ⇄ rhine-gateway ⇄ 角色（一个网关可承载多个角色）
```

## 支持的接口

| 方面 | 支持的内容 |
|---|---|
| 连接 | 连接器作为 WebSocket 客户端连接 `ws://<网关>:8791/v1/ws`，携带 `Authorization: Bearer <token>`。先发送 `hello`，收到 `welcome` 后开始通信。同一时间只保留一个连接器 |
| 会话 | 群聊和私聊。每个会话绑定一个角色（`chat_update`），一个网关可承载多个角色；绑定时可以补发最近的历史消息 |
| 上行：消息 | 文字、@ 某人和 @ 角色账号、引用、平台内置表情、图片、表情包（可附平台提供的描述）、链接卡片；语音、视频、文件、合并转发和其他消息只传一行说明 |
| 上行：图片 | 随消息内联，或只提供 ID、由网关按需请求（`get_media`）；可以先发缩略图、之后补发原图（`media_update`）；动图只传第一帧 |
| 上行：系统事件 | 撤回（可指明被撤回的消息）、拍一拍、进群退群等，传原文 |
| 上行：角色账号的消息 | 他人手动用该账号发送的消息、代掷骰子的结果 |
| 下行：回复 | 纯文字，可引用一条消息；一次回复最多分三条，带最早发送时间和过期时间 |
| 回执 | 发送成功回报 `message_sent`（带平台消息 ID），失败回报 `send_failed` 及原因 |
| 平台限制 | 连接器在 `hello` 中声明单条消息的字数上限和撤回时限，网关据此切分回复、处理撤回 |
| 可靠性 | 每个事件都有 `ack`；连接器按会话维护游标、断线后补发，网关按事件 ID 去重；连接器声明 `action_dedupe` 时，网关重启后补问未确认回复的结果 |

不支持的功能：网关不发送图片、表情包和语音，不发送真正的 @（需要指名时以引用代替），不撤回角色已发出的消息，不在无人发言时主动发起对话。

各字段的格式和约定见[连接器协议](protocol.md)。

## 连接器的职责

1. 使用共享 token 连接网关，发送 `hello`，声明角色使用的账号和平台限制。
2. 决定接入哪些会话、各由哪个角色回应（例如只接受主人发出的绑定指令），并用 `chat_update` 通知网关。
3. 上报已接入会话中的全部消息和系统事件，而不仅是 @ 角色的消息，因为角色依据上下文判断是否接话。收到 `ack` 后才视为送达。
4. 收到 `send_message` 后在原会话中发送，并回报结果。
5. 网关请求图片时，用 `media` 返回文件。

ID 由连接器生成，使用稳定且不透明的值（例如平台 ID 的 HMAC）；平台的原始账号保留在连接器一侧。

## 运行网关

```sh
# 生成连接器和网关共用的 token，仅所有者可读
mkdir -p ~/.config/ohmyrhine
python3 -c 'import secrets; print(secrets.token_urlsafe(32))' > ~/.config/ohmyrhine/gateway.token
chmod 600 ~/.config/ohmyrhine/gateway.token

uv run rhine-gateway --token-file ~/.config/ohmyrhine/gateway.token
```

| 选项 | 说明 |
|---|---|
| `-c`、`--config` | 配置文件，默认 `config.yaml` |
| `--host`、`--port` | 监听地址和端口，默认 `0.0.0.0:8791`。只接受本机和 `100.64.0.0/10` 网段的连接 |
| `--token-file` | token 文件，也可以用环境变量 `RHINE_GATEWAY_TOKEN_FILE` 指定 |
| `--debounce` | 私聊中最后一条消息之后等待多少秒再回应，默认 2.5 |
| `--echo` | 测试模式：不调用模型，被 @ 时原样回显，数据单独存放 |
| `-v` | 输出调试日志 |

## 回复行为

网关负责把握角色发言的时机，使其接近真人使用聊天软件的节奏：

- **私聊**：每条消息都回复；对方连续发送多条时，等对方停下后一并回复。
- **群聊**：被 @ 或被引用时必定回复；其余消息先由 `reply_judge` 判断角色是否会开口（未配置时，只在提到角色名字时回复）。判断出对方尚未说完时，先等待一段时间。有人要求角色暂时不要说话时，角色保持沉默，直到再次被 @ 或群里安静一段时间。
- **发送前复查**：回复生成后、发出前又有新消息时，该回复作废，连同新消息重新生成。
- **分条和节奏**：回复中的空行把回复分为多条，最多三条；两条之间间隔打字所需的时间。期间有人插话时，剩余部分不再发送。
- **撤回**：他人撤回的消息，角色可能已经看到；角色可以提及撤回，但不复述原文。
- **过期消息**：超过两分钟（默认值）的消息不再回复，以免回复与对话脱节。
- **系统指令**：在群聊或私聊中也可以下达系统指令，见[聊天](chat.md#在服务器上管理角色)中的指令码。

## 部署为服务

`deploy/deploy.sh [user@]host` 把项目同步到目标机的 `~/servers/ohMyRhine/`，安装依赖，生成 token，并安装 systemd 用户服务 `ohmyrhine-gateway`。目标机需要 rsync、uv 和 systemd。

- 首次部署时以 `config.example.yaml` 生成目标机的 `config.yaml`；之后的同步不改动目标机的配置和数据。
- 服务的额外参数写在 `~/.config/ohmyrhine/gateway.env` 的 `RHINE_GATEWAY_ARGS` 中，例如 `--echo`。
- 服务需要在用户退出登录后继续运行、开机自启时，为该用户启用 lingering：`loginctl enable-linger $USER`。
- `--no-restart` 只同步，不重启服务。
