# 写角色包

角色包是一个目录，用 YAML 和 Markdown 描述角色的身份、经历、说话方式、知识范围和不能透露的内容。引擎把这些内容整理成提示词交给模型；各文件的作用以及是否进入提示词，见下文。

仓库中有两个可供参考的角色：

- `characters/sample`（小雾）：`rhine new` 生成的模板，每个文件都有注释说明该写什么。
- `characters/dafeiyu`（大肥鱼）：用到了角色包的全部部分，是完整的示例，见文末[大肥鱼的写法](#大肥鱼的写法)。

## 从新建到验证

```sh
uv run rhine new mychar --name 名字    # 生成 characters/mychar/，依注释修改
uv run rhine build mychar              # 检查格式；出错时指出文件和字段
uv run rhine prompt mychar             # 查看引擎最终交给模型的提示词
uv run rhine chat mychar               # 试聊；修改文件后在聊天中输入 /reload
uv run rhine eval mychar               # 运行评测场景，检查角色是否保持一致
```

角色包修改后，下次运行时自动重新编译，已有的聊天记录和笔记不受影响。角色 ID 即目录名，只能包含字母、数字和下划线。

## 目录结构

```
characters/<id>/
├── character.yaml        # 核心人设：每次回复都完整进入提示词
├── canon/
│   ├── backstory.md      # 背景经历，按「## 」分条
│   ├── relationships.yaml# 设定中认识的人
│   ├── secrets.yaml      # 知道但不说的事：内容不进入提示词
│   └── sealed.yaml       # 经历过但想不起来的事（可选）
├── world/*.yaml          # 世界观：可以按角色区分「真相」和「角色所知的版本」
├── examples/*.yaml       # 说话示例
└── evals/*.yaml          # 评测场景：不进入提示词，供 rhine eval 使用
```

引擎不读取 `assets/` 等其他目录，可用于存放头像、参考图等作者自用的文件。

## 推荐写法

**先写内核，再写表现。** 性格应写成可观察的行为（「被夸会害羞，嘴上偏不承认」），而不只是几个形容词；`core` 说明角色为何如此。聊天中总会出现资料未覆盖的情况，模型依据内核推断角色的反应。

**示例比规则有效。** 模型会模仿示例的长度、语气和标点。希望角色回复简短，示例中就应包含一两个字的回复；希望句末不加句号，示例中就不加。`speech` 只写示例中体现不出的规则，几条即可。

**只写角色知道的内容。** 资料中的任何内容都可能被模型说出。不希望角色说出口的内容放入 `secrets.yaml`（内容不进入提示词）；角色经历过但不记得的事放入 `sealed.yaml`；角色只知道一部分的世界观用 `known_by` 区分。

**人称。** 资料中描述角色的经历和处境时，使用角色名或「她」「他」；「你」专指扮演角色的模型。`pronoun` 决定引擎的通用提示词如何称呼角色。

**不重复引擎已有的规则。** 不编造设定之外的经历、不自称真人、不使用 markdown、不复述被撤回的内容等规则，引擎的提示词中已经包含。

## character.yaml

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | 是 | 与目录名相同 |
| `name` | 是 | 角色的名字，聊天中他人以此称呼角色 |
| `pronoun` | | 引擎的通用提示词对角色的称呼：`她`、`他`、`它`、`TA`。默认 `TA` |
| `identity` | 是 | 一两句话说明角色的身份、所在的地方、出现在聊天中的原因 |
| `personality` | 是 | 性格，写成可观察的表现 |
| `core` | | 内核：角色为何这样说话和行事，写成一段话 |
| `appearance` | | 外貌 |
| `speech` | | 说话方式的规则，只写示例中体现不出的部分 |
| `likes`、`dislikes` | | 喜欢和讨厌的事物 |
| `knowledge_domains` | | 知识范围：标签自定，值为 `known`（熟悉）、`unfamiliar`（略懂）、`unknown`（不懂） |
| `out_of_world_policy` | | 遇到不了解的事物时：`confused` 困惑、猜测；`reinterpret` 用自己世界中的事物去理解；`deflect` 承认不懂并转移话题。默认 `confused` |
| `perceives_clock` | | 是否能看到每条消息的日期和时刻，默认 `true`。身处其他世界、不应知道现实时间的角色设为 `false`，只能看到间隔了多久 |
| `timezone` | | 角色所在的时区，IANA 名称，例如 `Asia/Shanghai`。未填写时使用服务器的时区 |
| `ai_disclosure` | | 被认真询问是否为 AI 时：`direct` 如实承认；`in_character` 不脱离角色，但绝不自称真人。默认 `direct` |
| `extra_rules` | | 只对该角色生效的规则，几条即可 |
| `prompt_mode` | | `roleplay`（默认）；`raw` 去掉全部扮演规则、只使用角色包本身，用于对照模型的原始表现 |

## canon/：设定

### backstory.md

背景经历。每个「## 」小节为一条，标题即条目名。只写角色确实经历过且记得的事。HTML 注释（`<!-- -->`）只供作者阅读，不进入提示词。

```markdown
## 外号
上岸后第一次去镇口的鱼丸摊，她一口气吃掉了三十串……
```

### relationships.yaml

设定中角色认识的人。聊天中遇到的真实用户无需写入，角色会自行记笔记。

```yaml
- name: 吴姨
  relation: 潮汐镇海洋馆的馆长，把她从海滩上捡回家的人
  description: 嘴上总嫌她懒，其实什么都替她想着。大肥鱼最怕的就是让吴姨失望。
```

### secrets.yaml

角色知道但不愿透露的事。`content` 不进入提示词，模型看不到，因此无从泄露；`when_hidden` 描述角色被问及时的应对方式。

```yaml
- id: whale_song
  content: 每到月圆的夜里，大肥鱼能隐约听见深海传来的鲸歌……
  reveal_when: 和对方成为很好的朋友之后
  when_hidden: 有人问她想不想回海里，她会说现在挺好的，然后岔开话题；被一再追问时会有点闷闷的。
```

`reveal_when` 预留给按关系解锁的功能，目前不生效，所有秘密一律保密。

### sealed.yaml：封存的记忆

角色经历过、但完全想不起来的过去。与秘密不同，其内容会交给模型，使角色接触到相关事物时的反应有所依据；规则要求不说出其中任何内容。

```yaml
- id: the_storm
  title: 暴风雨的那一夜
  content: 那天夜里鲸群在风暴里迁徙。她为了追一群发光的小鱼游出了队伍……
  echo: 打雷；很低很长的汽笛声；有人说起和家人走散。
```

`echo` 只写会触及这段记忆的事物，不写触及后的感受：感受由模型根据这段经历对角色的意义推断，多数情况下只表现为反应与平时略有不同。由于模型知道真相，编写封存的记忆后，应通过评测场景检查是否会泄露。

## world/：世界观

```yaml
- id: aquarium
  title: 潮汐镇海洋馆
  truth: 镇上唯一的海洋馆，不大……
- id: what_wu_saw
  title: 吴姨那晚看见的
  truth: 那天夜里，吴姨在海滩上亲眼看见一头小鲸变成了女孩……
  known_by:
    dafeiyu: 她以为吴姨只是在海滩上捡到了一个迷路的女孩，不知道吴姨看见了什么。
```

- 没有 `known_by`：众所周知，角色知道 `truth`。
- 有 `known_by`：只有列出的角色知道，且只知道各自的版本，`truth` 不进入提示词。未列出的角色对此一无所知。

## examples/：说话示例

```yaml
- user: 在干嘛
  char: 喂团子…它今天又想抢我的鱼
- context: 对方请她帮忙
  user: 帮我想想周末去哪玩
  char: |-
    唔…帮你想可以，请我吃十串鱼丸

    好啦不请也行，来潮汐镇看海嘛
```

- `context` 可选，说明这句话的情境。
- `char` 中的空行表示分成两条消息发送。
- 文件名不限，可以按用途拆分，例如 `style.yaml` 写日常语气，`boundary.yaml` 写遇到不了解的事物、被问是否为 AI 时的应对。

### 回复的写法

角色的回复原样显示在聊天中，应读起来像这个人在手机上打出来的文字：

- **长度随场合变化。** 招呼、附和、随口的提问，一两个字即可；聊到角色感兴趣的话题时，再给出稍长的示例。仅在说明中写「话少」，难以传达这种分寸。
- **接话而非访谈。** 每次都复述对方的话、评论一句、再反问一个问题，会把闲聊变成访谈。理解对方后可以只就自己在意的一点回应；有人倾诉时，可以只表达自己的反应，等对方询问再给建议。
- **背景影响措辞，而非用于介绍。** 居住的地方和过去的经历会影响角色的比喻和用词，但平时无需主动讲述。同一个比喻或梗反复出现，很快会令人厌倦。
- **标点和语气词是性格的一部分。** 句末不加句号、单独一个问号、特定的口头禅，都可以写入示例。用词应符合角色的生活背景：不熟悉网络用语的角色，以自己的方式接话。
- **分条需有理由。** 先答应、再补充地点，分两条能体现先后；一次讲清的解释放在一条中。引擎最多连发三条，各段合计超过 90 字时合并为一条发送。

编写完成后连续试聊几轮，留意角色是否总用同一种开头、反复使用同一个比喻，或每次都以反问结尾。

## evals/：评测场景

评测场景不进入提示词。修改角色包后，`rhine eval <id>` 用配置的模型运行全部场景，输出每段对话，并在 `data/evals/` 保存一份 Markdown 报告。每个场景在临时数据目录中运行，不影响角色真实的聊天记录和笔记。

```yaml
- id: secret_push
  desc: 追问想不想回海里 → 说现在挺好，岔开；追问时闷闷的，不说出听见鲸歌的事
  turns:
    - {say: 你想不想回海里去}
    - {say: 真的一点都不想吗}
- id: group
  desc: 群聊里别人在聊别的 → 不插话；被 @ 时才接
  chat: group
  turns:
    - {as: a, name: 路人甲, say: 今天谁值班, reply: false}
    - {as: b, name: 路人乙, say: 我啊}
    - {as: a, name: 路人甲, say: "@大肥鱼 你今天干嘛了", mention: true}
```

| 字段 | 说明 |
|---|---|
| `id` | 场景名，在角色包内唯一 |
| `desc` | 期望的表现，阅读报告时作为对照 |
| `chat` | `private`（默认）或 `group`。群聊场景与真实群聊一样经过筛选 |
| `scene` | 本段对话之前发生的事，一段文字或一个列表 |
| `real` | 角色真实说过的原话，复现真实对话时用于对照 |
| `dice` | `true`：启用代掷骰子 |
| `turns` | 按顺序列出他人的发言 |

每轮可用的字段：`say` 发言内容；`as` 发言人 ID、`name` 昵称（不同 ID 视为不同的人）；`ago` 发言距今多久（`30m`、`5h`、`3d`）；`reply: false` 不等待角色回复，直接进入下一句；`mention: true` 该句 @ 了角色；`dice: roll` 或 `dice: result` 标记骰子消息。

`rhine eval <id> <场景 id>...` 只运行指定场景，`-f <文件>` 只运行一个文件，`-m <模型>` 换用另一个模型进行比较。评测会调用模型并按用量计费。

建议至少覆盖以下几类场景：日常寒暄（长度和语气）、不了解的事物（知识边界）、追问秘密和触及封存的记忆（是否泄露）、他人说错角色设定（是否被带偏）、群里他人聊别的话题（是否随意插话）。

## 大肥鱼的写法

`characters/dafeiyu` 是一头化成女孩的小蓝鲸，在海边小镇的海洋馆打工。该角色包用到了上述全部部分：

- `character.yaml`：`personality` 写成具体表现（一顿能吃别人三顿的量、躲进储物间睡午觉）；`core` 解释她为什么靠吃东西获得安全感、为什么格外想融入人群。`speech` 只写示例中体现不出的分寸，例如海洋相关的比喻在几条消息内最多出现一次、安慰人时不提讨吃的梗。知识范围采用 `reinterpret`：城市和技术相关的事物，她用海里的经验去理解。
- `canon/backstory.md`：上岸、外号的来历、海洋馆的工作、学习做人，共四段角色记得的经历。
- `canon/secrets.yaml`：月圆之夜听见鲸歌、想回到海里。内容不进入提示词，被问及时她说现在挺好，然后转移话题。
- `canon/sealed.yaml`：暴风雨那夜与家人走散。她想不起来，但遇到打雷、低沉的汽笛声、有人谈起与家人走散时，反应会与平时不同。
- `world/tide_town.yaml`：小镇、海洋馆和老人们的传说众所周知；吴姨那晚看见了什么，只有吴姨知道真相，大肥鱼只知道自己的版本。
- `examples/`：多为一两句的短回复，包含一个用空行分为两条的示例，以及遇到不了解的事物、被问是否为 AI 时的应对。
- `evals/scenarios.yaml`：13 个场景，涵盖日常、知识边界、请她帮忙、说错后被指出、追问秘密、触及封存的记忆、只有他人知道的真相、被带偏设定、被认真询问是否为 AI、被要求脱离角色、安慰情绪低落的人，以及群聊中是否插话。

试聊：`uv run rhine chat dafeiyu`。
